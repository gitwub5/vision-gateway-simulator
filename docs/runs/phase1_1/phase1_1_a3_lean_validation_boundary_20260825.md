## Artifact Check

Minimal runs generated only the core ROI metadata files:

```text
roi_metadata/gate_decisions.jsonl
roi_metadata/rule_roi.jsonl
```

The following detailed diagnostics were not generated by default:

```text
roi_metadata/component_metadata.jsonl
roi_metadata/tile_metadata.jsonl
roi_metadata/policy_traces.jsonl
```

This confirms that baseline policy comparison does not require detailed component/tile trace artifacts.

## Interpretation

The A3 minimal contract preserves the A1/A2 decision:

- `tile_mask_recall_12x12` remains the recall candidate: higher ROI containment, more missed-target recovery, higher ROI/tensor cost.
- `hybrid_component_tile_cost` remains the cost/control candidate: same containment and effective reduction as component baseline, but records tile-driven selection metadata.
- `component_bbox_balanced` remains the compact baseline.

For `component_bbox`, selected tile count is now `0.000` in the minimal summary. Component tile metadata remains available only in full diagnostics, so the main report no longer implies that component tile metadata is part of the decision.

## Decision

A3 can close with the lean validation boundary:

- New policy experiments should pass minimal validation first.
- Full diagnostics should be enabled only when minimal metrics or visualizations show an unexplained regression.
- Main policy summaries should stay limited to target coverage, ROI/batch/tile counts, effective input reduction, fallback reasons, and latency/cost proxies.
